## 用 DeepSeek 官方 API

1. 在 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建 API Key。
2. 打开 dsh 的“设置 → 模型”。
3. 在 DeepSeek 卡片里填入 Key，保存。

保存后，下一次请求就会用到刚填的 Key，不需要重启服务。使用默认端点时，模型列表跟随 DeepSeek API 发布的内容：第一次需要模型时加载，使用期间大约每十分钟在后台刷新一次；加载失败时退回内置模型。

## 第三方提供商

“添加模型提供商”默认打开的是“第三方模型提供商”。列表里是 dsh 自带的提供商 id，例如：

| 提供商 | id |
|---|---|
| Anthropic | `anthropic` |
| OpenAI | `openai` |
| Kimi | `moonshotai` |
| GLM | `zai` |

选中提供商后填 API Key 并保存。端点、协议和模型列表由已安装的目录提供，不需要你手动填写。

认证提示的含义：

- 绿色：检测到环境变量
- 黄色：没有检测到凭据变量，需要输入 Key 或配置环境变量
- 状态未确认：读取失败

这些提示只检查变量是否存在，不验证 Key 是否有效，也不测试连接。

## 自定义 OpenAI 兼容端点

要接中转站、公司网关、自建服务器，或者目录里没有的提供商时，切到“自定义模型 API”，填写下面这些项：

- **Provider ID**：只用小写，永久有效，不能修改
- **显示名称**：界面展示用
- **基础 URL**：网关地址
- **API 协议**：三选一
- **凭据**：API Key
- **模型**：至少一个模型 ID

协议必须与网关实际实现一致：

| 界面选项 | 配置值 |
|---|---|
| OpenAI Chat Completions | `openai-completions` |
| OpenAI Responses | `openai-responses` |
| Anthropic Messages | `anthropic-messages` |

一个提供商只用一种协议。网关同时提供两种协议时，你要建两个提供商。

“模型目录”里的“获取可用模型”会向端点询问模型列表；这一步只是便利手段，不是每个网关都按常见格式作答。探测失败或列表为空时，手动添加模型 ID 即可，效果与自动获取相同。

## 密钥存在哪里

- 密钥是只写的：保存后界面只能读到脱敏描述符，不会回显明文。
- 凭据存储在 `$DSH_HOME/.credentials.yaml`，设置页只保留凭据引用。
- 已保存的凭据仍保持只写；输入框里的“显示密钥”只针对当前这次输入。

不要把 `$DSH_HOME` 目录提交到 Git，也不要把 Key 写进插件配置或截图。

## 常见错误

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 401 / 未授权 | Key 错误、过期或不属于该提供商 | 重新创建 Key，确认填在正确的卡片 |
| 模型不存在 | 模型 ID 与网关实际列表不一致 | 用“获取可用模型”或在网关侧确认 ID |
| 请求格式错误 | 协议选错 | 按网关实际实现切换三种协议之一 |
| 列表为空 | 网关不返回标准模型列表 | 手动添加模型 ID |
| 保存后仍用旧模型 | 当前会话仍持有旧配置 | 新建会话或等下一次请求 |

## 核验说明

本页按官方 `providers` 文档与 2026-10-31 的界面说明核对。**没有在本机使用真实 API Key 完成一次模型调用**，因此错误码与界面文案可能随版本变化；遇到不一致时以官方文档为准。
