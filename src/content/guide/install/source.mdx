## 需要源码安装的三种情况

只有三种情况值得用源码安装：

1. 要改 dsh 本身的代码
2. 要开发插件，插件得和在自己机器上跑起来的 dsh 一起调试
3. 要针对某个提交（commit）或分支复现问题、验证结论

如果你只是想用 dsh，用 [桌面版](./desktop.mdx) 或 [npx](./npx.mdx) 更快。

## 前置

- Node 与 npm
- **pnpm**：仓库按 pnpm workspace 组织（pnpm 的多包管理机制），依赖要用 pnpm 安装
- Git
- Windows 上可能还需要 C++ 构建工具，用来编译部分原生依赖

pnpm 不是可选工具。实测中，`dsh plugin` 这类命令会把操作转交给 pnpm 执行；本机没有 pnpm 时，命令直接报“不是内部或外部命令”。先确认本机装有 pnpm：

```bash
pnpm -v
```

pnpm 的安装方式和版本要求以官方 README 为准，本站不写死具体版本号；Node 版本变化之后，要回到 README 重新核对。

## 克隆与安装

```bash
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
```

仓库较大，第一次安装依赖会比较久。网络不稳时，先把 registry 或代理配置好，避免下载到一半失败、本机留下装不全的依赖。

## 构建与启动

```bash
pnpm run build
pnpm dsh web
```

官方 README 里还提供了 `pnpm run dev:web`，用于开发时监听源码改动并重建客户端。日常运行用构建后的产物即可。

启动后同样会打印带 token 的本地地址。直接用不带 token 的地址访问 3080 端口会返回 401，属于正常的鉴权行为，见 [npx 安装](./npx.mdx#确认服务起来了)。

## 更新

```bash
git pull
pnpm install
pnpm run build
```

官方还处于 developer preview（正式发布之前的预览阶段），破坏性变更（让你已有的配置或代码失效的改动）很频繁。更新之前先看 release 说明；生产环境用的 profile 不要直接指向 main 分支。

## 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `pnpm: command not found` | pnpm 未安装或不在 PATH | 先安装 pnpm，再重开终端 |
| `ERR_PNPM_...` 依赖解析失败 | lockfile 与 Node 版本不匹配 | 按 README 的 Node 要求切换版本，再重装 |
| Windows 下 node-gyp 报错 | 缺 C++ 构建工具 | 安装官方要求的构建工具链 |
| `EADDRINUSE` | 3080 被占用 | 结束占用进程或换端口 |
| 构建成功但页面空白 | 只构建了部分产物 | 用官方推荐的构建命令重新构建 |
