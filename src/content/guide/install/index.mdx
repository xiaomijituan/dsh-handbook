## 先做一个判断

三种安装方式不是新旧关系，而是三种使用场景。

- **不想碰命令行，只想有个能用的界面** → [桌面版](/install/desktop/)
- **在服务器、SSH 或脚本里跑，或者只想临时试** → [npx](/install/npx/)
- **要改源码、开发插件、跟最新提交** → [源码](/install/source/)

如果只是第一次用，选桌面版。它把 Node、Web UI 和服务进程一起打包了，少一层环境问题。

## 三种方式对比

| 方式 | 适合谁 | 前置与升级 |
|---|---|---|
| 桌面版 | 不写代码、不想管 Node | 要 API Key；升级时重新下载安装包 |
| npx | 有 Node 的开发者、服务器 | 要 Node、网络、API Key；升级时重跑 npx |
| 源码 | 插件开发者、贡献者 | 要 Node、pnpm、Git；升级时 `git pull` 后重新构建 |

核验程度：npx 的启动、401 鉴权与端口占用已实测；桌面版只核验了下载地址与文件大小；源码安装按官方 README 核对，未实测。

## 共同前置：API Key 与网络

三件事在三种方式里都一样：

1. **一个 DeepSeek API Key**：在 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建。Key 是写进本机配置的，不要提交到 Git 仓库。
2. **能访问安装源**：桌面版访问 `download.deepseek.com`，npx 与源码访问 npm registry 或 GitHub。
3. **一个工作目录**：dsh 会把它当成默认文件系统位置。第一次启动后还要在界面里选工作区。

## 装完怎么确认成功

按顺序做三步，不要跳过：

1. **页面能打开。** 桌面版会自动打开；npx 要用启动日志里带 `token` 的完整地址。
2. **设置 → 模型里能看到 DeepSeek 卡片。** 填入 Key 并保存。
3. **选工作区，新建会话，发一句话。** 没选工作区时，输入框不可用。

> **看到 401 不等于安装失败。** `dsh web` 默认对裸地址 `http://127.0.0.1:3080/` 返回 401，必须使用启动时打印的 `?token=...` 地址。原因见 [npx 安装](/install/npx/#确认服务起来了)。
