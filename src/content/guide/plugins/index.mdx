## 插件是什么

dsh 的设计是“一切皆插件”：模型适配器、工具、会话日志、界面和 Agent Loop 都可以拆成插件。

实际使用时有三个词要分清：

- **插件（plugin）**：一个可加载的模块，向系统注册工具、事件或界面。
- **组合包（bundle）**：一组插件的打包，安装时通常装的是 bundle。
- **profile**：一个独立保存的插件集合，有自己的目录和依赖记录。`web`、`tui`、`headless` 是随 dsh 提供的 profile。

所以遇到“装了插件但不显示”，你要先确认的是：**插件被装进了哪个 profile？**

## 第一批插件从自带组合包开始

dsh 的 web profile 自带插件管理器等基础 bundle，这些 bundle 不需要额外安装就能用。2026-10-31 用 `--dump-config` 导出的 profile 里能看到：

```text
- id: plugin-manager
  name: '@deepseek-ai/dsh-plugin-manager'
- id: tool-plugin-manager
  name: '@deepseek-ai/dsh-plugin-manager/tools'
- id: timer
  name: '@deepseek-ai/cordis-plugin-timer'
```

想知道某个 profile 里装了哪些插件，不需要模型 Key：

```bash
dsh --profile web --dump-config
```

`--dump-config` 也是排查“插件到底装没装进去”的最直接办法。

## 第三方插件安装前的四项检查

DSH 不内置任何第三方插件索引源。官方文档写明：要浏览和安装索引里的插件，需要先打开实验性的“自定义插件索引”组合包，然后在“发现”页添加索引文件的 URL。

也就是说，你看到的“插件市场”里的内容全部来自第三方。索引里的标题、描述、作者和来源都由索引提供方决定，DSH 只检查文件格式，不验证这些声明。

安装之前至少检查四件事：

1. **来源**：索引 URL 是否可信、是否使用 HTTPS。官方文档明确提醒，能控制 `http:` 索引内容的人，可以修改该索引列出的安装来源。
2. **版本兼容**：插件声明的 dsh 版本范围是否覆盖本机安装的 dsh 版本。
3. **维护状态**：最近一次更新是什么时候，仓库是否公开。
4. **权限**：插件会以你的权限运行，能读文件、执行命令。来源不明的插件不要装。

本站的第三方插件表只收录实际装过、并且记录过版本的插件条目。截至 2026-10-31，第三方插件实测还没有完成，因此不列推荐；“20 个必装”这类清单在没有实测记录之前无法核对。

## 三种情况下自己写插件更合适

当你要把内部工具接入 dsh、需要把一套工作流固定下来，或者现有插件的权限太大时，自己写一个最小工具插件更合适。

从 [写第一个插件](./first-plugin.mdx) 开始：先做一个只返回文本的工具，确认加载成功后，再考虑发布。
