## 插件是什么

dsh 的设计是“一切皆插件”：模型适配器、工具、会话日志、界面和 Agent Loop 都可以拆成插件。

实际使用时有三个词要分清：

- **插件（plugin）**：一个可加载的模块，向系统注册工具、事件或界面。
- **组合包（bundle）**：一组插件的打包，安装时通常装的是 bundle。
- **profile**：一套插件栈。`web`、`tui`、`headless` 是随 dsh 提供的 profile，每个 profile 有自己的插件集合。

所以“装了插件但不显示”，第一反应应该是：**它装进哪个 profile 了？**

## 第一批先看自带组合包

dsh 的 web profile 自带插件管理器等基础 bundle。不需要额外安装就能用。2026-10-27 用 `--dump-config` 导出的 profile 里能看到：

```text
- id: plugin-manager
  name: '@deepseek-ai/dsh-plugin-manager'
- id: tool-plugin-manager
  name: '@deepseek-ai/dsh-plugin-manager/tools'
- id: timer
  name: '@deepseek-ai/cordis-plugin-timer'
```

想看自己的 profile 里有什么，不需要模型 Key：

```bash
dsh --profile web --dump-config
```

这也是排查“插件到底装没装进去”的最直接办法。

## 第三方插件怎么判断

DSH 不内置任何第三方插件索引源。官方文档写明：要浏览和安装索引里的插件，需要先打开实验性的“自定义插件索引”组合包，然后在“发现”页添加索引文件的 URL。

也就是说，你看到的“插件市场”是第三方内容。索引里的标题、描述、作者和来源都由索引决定，DSH 只检查文件格式，不验证这些声明。

装之前至少检查四件事：

1. **来源**：索引 URL 是否可信，是否使用 HTTPS。官方文档明确提醒，能控制 `http:` 索引的人可以修改其中列出的安装来源。
2. **版本兼容**：插件声明的 dsh 版本范围是否覆盖你当前的版本。
3. **维护状态**：最近一次更新是什么时候，仓库是否公开。
4. **权限**：插件会以你的权限运行，能读文件、跑命令。来源不明的插件不要装。

本站的第三方插件表只收录实际装过、记录过版本的条目。截至 2026-10-27，还没有完成第三方插件实测，因此不列推荐；这比编一份“20 个必装”更可靠。

## 什么时候该自己写

当你要把内部工具接进来、需要固定工作流，或者现有插件的权限太大时，自己写一个最小工具插件更合适。

从 [写第一个插件](/plugins/first-plugin/) 开始：先做一个只返回文本的工具，跑通加载，再考虑发布。
